# Inventory Management API

A backend REST API for managing product inventory and tracking stock movements, built with FastAPI and PostgreSQL.

> **Project status: early development.** Only product creation exists so far. This README separates what is verified from what is still being built. See [Project Status](#project-status).

## Overview

The API keeps product records and a history of stock movements for each product. The central design goal is consistency: a product's recorded quantity should always agree with its movement history.

This project is also a learning project. It is built to practise a layered architecture, transactional database operations, schema migrations, and a test setup that refuses to run against the wrong database.

## Database Design

### `products`

| Column | Description |
|--------|-------------|
| `id` | Primary key, generated by PostgreSQL Identity |
| `name` | Product name |
| `description` | Optional description |
| `price` | Price, `NUMERIC(10,2)` |
| `quantity` | Current recorded stock quantity |
| `is_deleted` | Soft-deletion flag (not used by any endpoint yet) |
| `created_at` | Creation timestamp |
| `updated_at` | Update timestamp (not yet updated automatically) |

Database constraints reject negative prices and negative quantities.

### `stock_movements`

| Column | Description |
|--------|-------------|
| `id` | Primary key |
| `product_id` | Foreign key to `products.id` |
| `movement_type` | Type of movement (free text in the database for now) |
| `quantity_change` | Quantity involved in the movement |
| `new_quantity` | Recorded quantity after the movement |
| `reason` | Optional explanation |
| `created_at` | Movement timestamp |

The foreign key uses `ON DELETE RESTRICT`, so a product that has movement records cannot be deleted.

## API

### `POST /products/`: create a product

Creates a product and records an opening stock movement for it.

**Request body**

| Field | Rules |
|-------|-------|
| `name` | Required. 1 to 100 characters after trimming whitespace. |
| `description` | Optional. Up to 500 characters, or `null`. A blank string is stored as `null`. |
| `price` | Required. 0 or more, at most 2 decimal places, at most 10 digits in total. |
| `quantity` | Whole number from 0 to 1,000,000. Defaults to 0. |

**Example request**

```json
{
  "name": "Wireless Mouse",
  "description": "Wireless optical mouse",
  "price": "12500.00",
  "quantity": 20
}
```

**Example response** (`201 Created`)

```json
{
  "id": 1001,
  "name": "Wireless Mouse",
  "description": "Wireless optical mouse",
  "price": "12500.00",
  "quantity": 20,
  "created_at": "2026-01-01T12:00:00+00:00",
  "message": "Product added successfully"
}
```

The values above are an example. `id` and `created_at` will differ.

Invalid input returns `422 Unprocessable Entity`.

The opening movement uses movement type `opening balance`, with `quantity_change` and `new_quantity` both equal to the initial quantity.

## Getting Started

### Prerequisites

- Python 3.10 or newer (developed with 3.13)
- PostgreSQL
- Git

### 1. Clone the repository

```bash
git clone https://github.com/chisomjohnpaul48-wq/Inventory_Management_api.git
cd Inventory_Management_api
```

### 2. Create and activate a virtual environment

```bash
python -m venv .venv
```

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

```bash
# Linux / macOS
source .venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Create the databases

Create two empty databases, one for development and one for tests (in pgAdmin, or in `psql`):

```sql
CREATE DATABASE inventory_db;
CREATE DATABASE inventory_test;
```

The test database **must** be named `inventory_test`. The test suite refuses to run against any other name.

### 5. Configure environment variables

Create your local environment file from the example:

```powershell
Copy-Item .env.example .env
```

Edit `.env` and provide your PostgreSQL credentials:

```env
DATABASE_URL=postgresql://username:password@localhost:5432/inventory_db
TEST_DATABASE_URL=postgresql://username:password@localhost:5432/inventory_test
```

Optional settings, with their defaults:

```env
APP_NAME=Inventory Management API
DEBUG=False
```

Replace the placeholder credentials with your own values.

> **Important:** Never commit `.env` or real database credentials.

### 6. Apply migrations

Alembic uses the environment selected through the `-x environment` argument in `migrations/env.py`.

Apply migrations to the development database:

```bash
alembic -x environment=app upgrade head
```

Apply migrations to the test database:

```bash
alembic -x environment=test upgrade head
```

Each database maintains its own migration revision.

Both commands work on Windows, Linux, and macOS, provided Alembic is available in the active virtual environment.

### 7. Run the application

```bash
uvicorn app.main:app --reload
```

- API: `http://127.0.0.1:8000`
- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

## Testing

```bash
pytest
```

Current automated tests cover the **database safety checks** only:

- The test database name must be exactly `inventory_test`.
- The live connection is checked before any data is deleted.

The test setup also provides a session-scoped test client and empties the `products` and `stock_movements` tables before each test.

> **Warning:** the test fixture truncates `products` and `stock_movements` before every test. Never point `TEST_DATABASE_URL` at a database containing data you need.

There are no automated tests for the API endpoints yet.

## Migrations

```bash
alembic upgrade head     # apply all pending migrations
alembic current          # show the current revision
alembic history          # show migration history
```

Each database tracks its own revision, even when several databases use the same migration scripts.

### Known limitations

- `movement_type` is free text in the database, with no check constraint. The opening balance value is stored as `opening balance`.
- A stock movement is recorded even when the initial quantity is 0.
- The app requires `TEST_DATABASE_URL` to be set in order to start, even outside testing.
- `updated_at` is set when a product is created but is not yet updated automatically.

### Planned

- Product retrieval and listing.
- Product updates. Changing a product's quantity will automatically record an `adjustment` stock movement.
- Soft deletion. A product with stock above zero will not be deletable unless its stock is first reduced to zero, with the reduction recorded as a movement.
- Stock movement operations and history.
- Custom exception handling for API errors.
- Automated tests for the API endpoints.
- Cleaner `movement_type` values, enforced by a database constraint.
- Moving tests to a top-level `tests/` folder.
